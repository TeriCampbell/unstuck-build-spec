Input fields

What the AI receives, by prompt. Student-facing fields come from wireframe screens; system fields are added by the application. Tone is not a student input; it lives in the system prompt. Students can type in optional, character-limited text boxes on specific screens; those are not a separate chat product mode.

Overview

Text input vs. chat: Unstuck includes optional free-text fields (situation, check-in, plan update) with character limits and distress screening on every submission. It does not offer a general-purpose chat thread where the student and model go back and forth without structured intake. Required inputs are mostly structured selections and dates; free text adds context when the student chooses to use it. See optional fields, Screening, and Journeys.

Optional student fields

Optional for the student; when present, screened and passed to the model. Hidden entirely for flagged accounts (no placeholder).

Field Format Source Used by prompt(s) Impact on output
Situation free text Max 280 characters Screen 05 — per selected checkbox
“What is the most urgent thing on your plate right now?”		 Screening → Master Calibrates acknowledgment and prioritization; merges with checkbox context. Plan still generated from checkboxes alone if skipped.
Check-in barrier text Max 140 characters Screen 10 — only if “attempted but could not complete” Screening → Adaptive replanning Short context for why a step stalled; informs replan tone and sequencing. Not shown for yes / no / in progress.
Plan update free text Max 280 characters Screen 13 — alongside change-state checkboxes Screening → Plan update Adds nuance to deadline shifts, new items, or time conflicts. Pre-selects alone can drive update for flagged users.

Distress screening prompt

Lighter Claude model. Returns classification only; UI handles student-facing responses. Runs before plan prompts when free text exists.

Field Format Source Required
Free text submitted in session One batched payload (situation and/or plan-update text on first session; check-in text on replan session) Screens 05, 13, or 10 (conditional) Yes (≥1 string to classify)
Field origin metadata Which surface submitted text (situation | plan_update | check_in) Application Yes

Output: Tier label only (standard, elevated concern, crisis, inappropriate/threatening).

Not sent to the AI

Collected for product behavior, compliance, or analytics; not in plan-generation payloads in v1.

Data Why not in model payload
Account email, OAuth identifiers Authentication only
Trusted contact name, permissions, notification prefs Routing and sharing UI; not used for plan content in v1
Resource include / exclude / ask me later choices UI and toolkit state after plan is shown; informs future sessions, not initial generation input
Counselor dashboard configuration (screen 16) Deferred post-capstone; screen 15 uses live SQL aggregates, not per-school config UI
Click events on resource links Analytics events in database, not LLM input
