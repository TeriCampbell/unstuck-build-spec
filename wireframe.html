Student screens (01–14)

# Screen Route Fields / data collected AI Journeys
01 Home / Landing unstuck.app Auth choice (Google, email, login). No AI input. None All
02 Account creation & age gate /signup Email; month/year of birth; optional state, school type; grade level (→ master prompt). None first-plan, account
03 Trusted contact setup /setup Contact name, email; visibility checkboxes. Optional, skippable. Not sent to plan prompts in v1. None first-plan, account
04 Student dashboard /dashboard Read-only plan, toolkit, ask me later. Actions: next step, plan update, view toolkit. No new intake fields. Triggers continuation or update prompts (buttons) return, checkin, first-plan
05 Situation selection /start Multi-select situation checkboxes; optional 280-char text per selection (screened). Hidden if flagged. Screening → Master (after 06–07) first-plan, flagged
06 Intake flow /intake Per task: name (dropdown), due date, deadline type. Structured only. Feeds master first-plan
07 Clarifying questions /clarify Available time; started status; difficulty; deadline changes since entry. No free text (v5). Feeds master first-plan
08 Plan delivery /plan Displays model output: acknowledgment, full-scope plan, seven-day steps; include/exclude/ask me later per resource; optional share plan. Master output rendered here first-plan, crisis
09 Toolkit view /toolkit Resource cards, open-link clicks (analytics). Not LLM input. None return, checkin
10 Check-in response /checkin?token=… Per task: yes / in progress / no / attempted but could not complete; optional contact counselor; conditional 140-char barrier text (screened). Screening if text → feeds replan checkin, return
11 Progress summary /progress Summary from check-ins; confidence radio (metrics, not plan prompt). Button to update plan. None (display) checkin, return
12 Crisis resources /support No plan. 988, Crisis Text Line, trusted contact notify (confirmed). Triggered by screening tier or behavioral patterns. UI response to screening / behavior (no plan prompt) crisis, all paths
13 Plan update /update Change-state checkboxes (≥1); optional 280-char text (screened). Prior plan loaded from DB. Screening → Plan update return
14 Flagged user state (example) /start Same as 05 without free text fields. Demonstrates account state, not a separate happy-path screen. Master / update / replan without free text flagged

Counselor screens (15–17)

Capstone prototype uses fabricated aggregate data. Student plan library remains system prompt in v1.

# Screen Route Fields / data AI Journeys
15 Counselor dashboard /counselor/dashboard Aggregate sessions, categories, resource engagement, contact request count; grade filter. Pattern observation (demo copy in wireframe; LLM post-v1). Post-v1 aggregate LLM counselor
16 Resource configuration /counselor/resources School-specific resources by category; AI suggest add resource (prototype). Static demo in v1 for student-facing generation. Suggestions (prototype) counselor
17 Contact request notification /counselor/notifications Student name, timestamp, support flag. Session content not shared. None counselor, checkin

Common paths (screen order)

New student → first plan

01 → 02 → 03 → 05 → 06 → 07 → [screening] → 08 → (09 toolkit as needed)

Return → next step only

01 or 04 → continuation prompt → updated focus on 04 / 08

Return → plan update

04 → 13 → [screening if text] → 08

Check-in → replan

Email link → 10 → 11 → (login) 04 or replan session → adaptive replan → 08

Crisis / elevated

Can interrupt after 05, 07, 10, or 13 screening → 12. Plan may exist but delivery gated.
