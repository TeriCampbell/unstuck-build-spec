ID cheat sheet

Primary keys and foreign keys in Postgres are UUID (v4), generated in the browser or server — not student names or emails. pilot_code is plain text entered at intake.

NameFormatSame asStored whereMeaning
visitor_idUUID—localStorage + sessions.visitor_idSame anonymous student across visits on this browser
session_idUUIDsessions.idlocalStorage + plans, events, check_ins, …One engagement episode (new per intake, return, or check-in visit)
prior_session_idUUIDFK → sessions.idlocalStorage + sessions.prior_session_idEarlier session whose plan is being updated
school_idUUIDschools.idIntake draft + sessions.school_idInstitutional rollup key (from pilot code lookup)
plan.idUUIDplans.idDB onlyInternal plan row; app loads by session_id or visitor_id
pilot_codetextschools.pilot_codeIntake UI onlyPILOT-A / DEMO → maps to school_id
grade_levelsmallint—Intake + sessions.grade_level9–12 for counselor filters

Rule: visitor_id = who on this browser. session_id = which visit. New session per return visit — load prior content via visitor_id.

Browser storage keys (localStorage)

The capstone app stores anonymous continuity in the browser’s localStorage API (not in Supabase until a plan is saved). Each row is one key your code reads or writes.
