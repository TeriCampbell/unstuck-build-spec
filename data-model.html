Goals

  1. Student: Generate and retrieve a plan across visits (visitor_id + new session_id per episode).
  2. Product: Tie structured session content to grade and school for learning and iteration.
  3. Counselor value prop: Aggregates only — not individual student profiles in the UI.
  4. Pilot / QA: Same tables for demo seed (is_demo) and real testers.
  5. Events: Meaningful actions (screens, resource clicks) — no full clickstream or PII in analytics.

plans · intake_snapshots · check_ins · events

intake_snapshots: one JSON payload per session at plan time. plans: plan_json + prompt version. check_ins: structured per-task responses (no free text). events: screen_viewed, plan_generated, resource_link_clicked, etc.
