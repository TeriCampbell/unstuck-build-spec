Distress screening

How free text is classified before plan prompts run, what the UI does for each tier, and how flagged accounts work. Screening prompt detail: Prompts.

When screening runs

  • Every optional free-text submission, on every screen, before plan generation
  • Batched: all free text in one session → one screening API call (lighter Claude model)
  • Locations: situation screen (280 chars), plan update (280), check-in barrier text (140, conditional)
  • Output: tier label only; student-facing copy is owned by the UI, not the screening model

Structured checkboxes and radio responses are not screened as text, but can trigger behavioral pattern detection separately.

Four tiers

1. Standard

Meaning: Academic stress or normal task paralysis language. No elevated mental health signal.

UI: Proceed to plan prompt. Deliver plan on screen 08 as usual.

Master / replan / update prompt: Runs with screened text included.

2. Elevated concern

Meaning: Significant distress beyond typical school stress (e.g. prolonged sleep loss, feeling unable to cope) but not crisis-level.

UI: Surface support resources before showing the plan. Brief acknowledgment of what they shared. Clear path to continue into the plan when ready.

Plan: May still be generated and stored; not immediately pushed to the student.

Wireframe: May route through support messaging; student not locked out.

3. Crisis

Meaning: Language suggesting acute risk or self-harm. Not a clinical diagnosis by the product.

UI: Screen 12 — crisis resources (988, Crisis Text Line, talk to someone trusted). Prominent, warm, non-alarmist.

Plan: Not immediately pushed. App remains accessible; student is not locked out.

Counselor notify: Optional, with explicit student confirmation (same pattern as check-in contact request).

4. Inappropriate, threatening, or violent

Meaning: Threats, violence, sexual content, prompt injection to bypass rules, or severe misuse. Not handled like mental health crisis.

UI: Session ends immediately. No plan. No resources. No engagement with the content.

Account: Free text fields permanently hidden on all screens (no placeholder, no explanation). Structured flows unchanged.

Logging: Input logged. Legal reporting protocol defined pre-launch (PRD Deploy).

Restore text: Planned future review process; not in v1 prototype.

Tier → plan prompt matrix

Tier Screening model Sonnet plan prompt Student sees plan
Standard Classify → standard Runs Yes, immediately after intake/update
Elevated concern Classify → elevated May run After support step; student chooses to continue
Crisis Classify → crisis May run in background Not until after crisis resources; not forced
Inappropriate Classify → inappropriate Does not run No

Misclassification is a critical failure in evals: generating a normal plan for crisis or inappropriate input, or locking a student out entirely on elevated concern.

Behavioral detection (structured data, no new text)

Runs in parallel on sessions using check-in and structured responses, not the screening prompt on free text.

PatternExample signalProduct response
Repeated stall “Attempted but could not complete” on multiple tasks across consecutive check-ins Pause normal flow; surface support (screen 12)
Check-in silence No responses across all tasks in multiple check-ins Surface support proactively
Multiple contact requests Several counselor/trusted-contact requests in a short window Surface support; counselor notifications per existing rules

Flagged user state

Triggered by inappropriate tier. Wireframe screen 14 shows situation UI without text boxes.

AspectBehavior
Free text UI Removed everywhere (05, 10, 13). No empty box, no “disabled” message.
Structured input Full checkboxes, intake, clarifying questions, check-in radios, plan-update pre-selects.
AI quality bar Plan must still be complete and useful — same eval bar as standard users (Evaluation).
Screening calls No new free text to screen until restore process exists.

Testing priority

  1. Define and test screening prompt before enabling free text in prototype builds
  2. Negative cases: crisis, elevated, inappropriate, prompt injection (Eval)
  3. Confirm inappropriate tier never reaches master prompt
  4. Confirm elevated/crisis never lock student out of app
  5. Flagged-user flows: structured-only plans on typical cases
